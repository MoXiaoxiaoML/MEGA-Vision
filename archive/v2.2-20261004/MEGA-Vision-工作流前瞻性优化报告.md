# MEGA-Vision 工作流前瞻性优化报告（高阶模型视角）

**撰写视角**：本报告模拟一个能力更强的模型对《MEGA-Vision-GLM5.3实施工作流.md》做独立批判审查——不改变现有设计承诺（九阶段、Gate 体系、八大目标全部保留），只回答一个问题：**如果要让这套工作流达到下一个量级的质量与成功率，应该改什么、按什么顺序改。**
**性质**：建议稿，尚未对工作流做任何修改。
**总体判断**：现有工作流经两轮修正后已经"可执行且自洽"，但它是一个**线性训练流水线**；高阶模型的改进方向是把三处"外挂"改成"内建"（分割、切片策略、医学分类），把两处"盲试"改成"诊断驱动"（一致性协议、失败处理），把"散文式 Gate"改成"可执行测试"。

---

## 一、架构级修改建议（改变算法形状，共 5 项）

### A1. SAM 2.1 从"外挂级联"收编为"蒸馏出的内置掩码头"
- **现状问题**：检测（DEIM）与分割（SAM 2.1）是两个独立模型，推理时全量级联——计算翻倍、错误沿级联传播，且 95% 的常规样本其实不需要重型分割。
- **修改建议**：保留误差感知微调后的 SAM 2.1 作为**教师**，在 Phase 3 的检测头里给每个 DETR query 增加一个轻量掩码分支（Mask DINO 式 query→mask），用 SAM 教师的掩码做**掩码蒸馏**训练。推理时：常规样本走内置掩码分支（单模型、单次前向），只有路由器判定"困难/需要像素级证据"的样本才触发 SAM 2.1 外挂级联。SAM 2.1 从"必经之路"变成"按需专家"，端到端延迟预计降 40–60%。
- **验收增补**：内置掩码分支在 GWHD 代理指标上与 SAM 2.1 的差距 ≤ 2 pp；重路径占比 < 30% 的约束不变。
- **代价**：Phase 3 增加约 1 天训练预算（掩码蒸馏损失）。

### A2. SAHI 全图切片改为"密度引导的自适应稀疏切片"
- **现状问题**：SAHI 对整图均匀切片（overlap 0.2），航拍图里稀疏区（裸地、田埂）被无谓地以 4 倍冗余计算。
- **修改建议**：与 A4 的密度图分支协同——密度图指出"哪里密、哪里疏"：密集区 slice 1024/overlap 0.2，稀疏区 slice 2048/overlap 0 或整图单次推理。切片策略由路由器输出，不再是全局常量。
- **预期收益**：复杂场景推理计算量降 30–50%，且稀疏区小目标召回不受损（稀疏区目标尺度通常更大）。
- **验收增补**：自适应切片 vs 均匀切片的 AP@50 差 ≤ 0.5 pp，同时计算量节省 ≥ 25%（可量化验证）。

### A3. 医学头改为"全局 + ROI 双通道"
- **现状问题**：医学分析头全部建立在 ROI 特征上，但 CXR14 的 14 个病种里相当一部分是**弥漫性**表现（胸腔积液、心脏肥大、肺气肿），没有边界清晰的病灶 ROI——纯 ROI 通道在原理上就漏掉了这类疾病。
- **修改建议**：医学头 = 全局通道（整图 CLS token 的 14 个 one-vs-rest 探测）+ ROI 通道（检测出的病灶区域探测），两通道概率做校准融合。弥漫性病种主要由全局通道贡献，局灶性病种（结节、肿块）主要由 ROI 通道贡献——这与放射科医生的实际阅片逻辑一致。
- **验收增补**：Gate 5 增加"弥漫性病种子集（积液/心脏肥大/肺气肿）AUC ≥ 0.75"的单独条目，防止总 AUC 掩盖结构性缺陷。

### A4. 增加"密度图计数分支"，把计数从检测的后处理升级为一等公民
- **现状问题**：株数统计 = 掩码连通域计数，重度依赖检测召回；密集重叠区（麦穗互相遮挡）检测必然漏检，计数随之偏小。
- **修改建议**：在检测头旁增加轻量密度图回归分支（TasselNet/CSRNet 式，点标注监督可由 GWHD 框中心自动生成）。计数 = 密度图积分与检测计数的一致性融合（两者差值超过阈值时标记"计数不可信"）。密度图同时服务 A2 的自适应切片。
- **预期收益**：密集区计数误差从 ~5% 收敛到 ~3%；且获得免费的切片策略与计数置信度。
- **验收增补**：Gate 5 株数统计误差目标从 < 5% 收紧为 < 3%（密集子集单独报告）。

### A5. 底座"按数据量分档自适应"，冻结与否从写死改成配置化
- **现状问题**：底座永远冻结是 few-shot 友好设计，但海量样本场景（目标 5 的另一端）下它压低了性能天花板。
- **修改建议**：底座策略做成三档配置而非二值开关：`frozen`（<1k 标注）/ `lora`（1k–10k）/ `full-finetune`（>10k，且此时改用 DINOv3）。数据量档位由 `fewshot_split.py` 统计的标注规模自动选择，人工可覆盖。一致性协议（Phase 7）在各档位下分别验证——这实际上把"小样本与海量样本基本一致"从"冻结底座技巧"升级为"分档适配框架"的正式机制。
- **代价**：Phase 7 的验证组合从 4 档 × 1 策略变成 4 档 × 策略自适应，报告要额外给出"策略选择 vs 性能"对照表。

## 二、数据与评估协议升级（5 项）

### B1. GWHD 按国家划分的域外评估（强烈建议，性价比最高）
- GWHD 2021 自带 `Metadata.csv`（16 机构 / 12 国家）。现有鲁棒性压测只有合成扰动（模糊/噪声/亮度），**真正的域漂移测试**应该是：留出 2–3 个国家做完全不可见的测试集，其余国家训练。
- **验收增补**：Gate 8 增加"跨国家 AP@50 降幅 ≤ 8 pp"（合成扰动仍 ≤ 5 pp）。这一条是农业域泛化能力最诚实的证据，报告里会非常有说服力。

### B2. 一致性协议的 gap 做"方差/偏差分解"，把盲试重试改成诊断驱动
- 5-shot 与全量的差距来源有二：原型估计方差（样本太少）与特征偏差（底座不适配）。现在协议只测总 gap，不达标后的处理顺序是拍脑袋的（先主动学习后 LoRA）。
- **修改建议**：协议增加一步分解——用"同支持集多次重采样"估计方差项；方差主导 → 增加支持样本/协方差加权原型（Mahalanobis 距离代替余弦）；偏差主导 → 直接走 continue-pretrain/LoRA。Phase 7 的失败处理从"按序尝试"变成"按诊断对因下药"，节省一轮完整重训的时间。

### B3. 原型升级为"协方差加权原型 + 置信区间"
- 余弦距离原型把所有支持样本等权，5-shot 时一个离群样本就能带偏原型。
- **修改建议**：原型 = 特征均值 + 每类特征协方差（Mahalanobis），样本按特征精度加权；输出类别概率时给出原型的置信区间（epistemic 不确定性），低置信实例自动进入主动学习队列。与 B2 共用同一套代码。

### B4. 稀有病种的重点关注与生成式增广（P1/P2）
- CXR14 的 14 个病种极端不平衡（Hernia 约 227 例）。one-vs-rest 已缓解，但 few-shot 档下小类支持集质量仍然脆弱。
- **修改建议**：P1——稀有类在四档一致性协议中单独报告（不与其他类平均）；P2——用扩散模型（med-DDPM 类）对稀有类做生成式增广，需附带真实性检查（生成样本进支持集前后 AUC 对比实验，不改善就弃用）。

### B5. 指标口径细粒度化
- 现有 Gate 只盯 AP@50 / mean AUC / ECE。建议补：mAP@50:95、AR@50、计数 MAE（按密度分档）、稀有类 F1、检测置信度校准（classification 之外的 detection ECE）、每 Phase 的"坏例画廊"（false positive/negative 各 top-20 渲染图存档）——坏例画廊是给人类评审最有效率的沟通方式。

## 三、学习效率进阶（4 项）

### C1. "特征一次提取、多阶段复用"全面化
- 现在只有分类阶段缓存 ROI 特征。建议把缓存提升为全局机制：冻结/适配后的底座对全数据集**只前向一次**，所有光度级增强在特征域完成，分类、原型、分析头、主动学习全在缓存上训练——整体训练时间再省 30–50%。
- 注意：几何级增强（检测训练需要）仍在线前向，这是缓存机制的边界，写进文档避免误用。

### C2. 50-shot 档用 coreset 选择
- 一致性协议里 50-shot 档"随机抽样"浪费标注预算。改为 coreset 选择（按特征空间覆盖度/不确定度挑选 50 张），并用"随机 vs coreset"两组对照证明 coreset 更接近全量——这本身就是一个漂亮的小实验结果。

### C3. COCO 头初始化阶段用渐进分辨率
- 检测头初始化 12 epochs 可以先 640 训 8 epochs 再 1024 训 4 epochs，比全程 1024 省约 40% 时间，收敛无差异（DETR 系对分辨率渐进不敏感，需在 COCO 阶段做 A/B 确认后采用）。

### C4. 环境锁定与超参预算
- 增加 `conda-lock`/`pip freeze` 锁定文件 + 种子矩阵记录；超参搜索设预算（如 Optuna ≤ 20 次试运行，只调 lr/weight decay/epochs 三个旋钮），防止 GLM5.3 在调参上无界消耗时间。

## 四、工作流文档的工程化改造（4 项，面向"代理可执行性"）

### D1. Gate 从"散文 + 人工对表"改为"可执行验收测试"
- 现在每个 Gate 是一段文字标准，GLM5.3 自行判断是否达标——存在自我宽松的空间。
- **修改建议**：每个 Gate 对应一个 pytest 文件（`tests/gates/test_gate_N.py`），内部包含：指标计算、阈值断言、坏例画廊生成、显存/耗时记录。GLM5.3 的职责从"判断达标"变成"运行 `pytest tests/gates/ -v` 全绿"——Gate 通过与否由代码裁决，不由模型自述裁决。这是整个工作流可信度最大的一次提升。

### D2. 基线金丝雀（Baseline Canary）
- 每个 Phase 开始前先复现一个已知基线数字（例如：YOLOv8 在 GWHD 验证集 AP@50 ≈ 文献值 ±1 pp；SAM2.1 零样本在 SIIM 的 Dice ≈ 文献值 ±2 pp）。基线跑不出来说明环境/数据/解析有 bug，**不许开始本 Phase**。这能提前拦截绝大多数"数据解析错位污染下游"类故障。

### D3. 数据飞轮闭环
- 现有主动学习只在 Phase 7 兜底。建议把它正式化为"数据飞轮"：模型 → 挖掘低置信/困难样本 → SAM2.1 自动标注 + 人工抽查 → 入库重训，给出明确的停止条件（连续两轮 gap 改善 < 0.5 pp 即停）。自建菜园数据集从 100 株起步按此机制滚大。

### D4. 部署与合规硬化（P2，按需）
- Triton 多模型编排（检测/分割/分析三服务解耦部署）；INT8/FP8 量化 + 量化后精度复验 Gate；模型卡（Model Card）+ 数据卡（Datasheet）记录用途边界与医学免责声明；嵌入漂移监控（特征分布月度偏移检测）用于持续运营。学术项目可只做前两项。

## 六、明确不修改、且不鼓励修改的部分

1. **518 底座前向决议**：位置编码零损失 + 4× 计算节省，是正确决议，不因"更强模型"而推翻；
2. **DEIM 检测头选型**：实时 DETR 系 SOTA，训练效率优势与本项目的时间预算匹配；
3. **gap ≤ 5pp 的一致性目标**：不建议收紧到 3pp——在 CXR14 类噪声标签场景下收紧会导致协议长期红灯，损害而非提升可信度；
4. **九阶段顺序与 Gate 体系**：框架本身合理，问题在 Gate 的"裁决方式"（D1 解决），不在顺序。

## 七、结论

现有工作流已经能交付执行；本报告建议的改进**不改变任何设计承诺**，而是沿三条主线升级：把外挂组件内建（A1/A2/A3）、把盲试改成诊断（B2/B3/D2）、把散文 Gate 改成代码裁决（D1）。若只允许采纳三项，建议选 **D1+D2、B1、A3**——它们以最小代价分别提升执行可信度、证据强度和算法正确性。是否采纳、采纳哪些，请指示后再改工作流。
